# Boundary Library

This local GeoJSON library is retained only for advanced/legacy maintenance and reference workflows. The current ordinary map Builder automatically selects one of the ten fixed templates in `assets/maps/templates/manifest.json`; it and the ordinary page do not read or render these Boundary files.

`boundary-index.json` remains a lightweight alias lookup for retained legacy tools. For example, `广东`, `Guangdong`, and `CN-GD` resolve to the same file.

## Format and coverage

- `countries/`: selected international-travel countries, GeoJSON.
- `china-provinces/`: province-level administrative regions of China, GeoJSON.
- `major-cities/`: selected Chinese cities, GeoJSON.
- `boundary-index.json`: canonical IDs, Chinese/English names, codes, and aliases generated by `scripts/build-boundary-index.mjs`.

The upstream-derived filename `guangzhou-province.geojson` contains Guangdong province geometry. It is retained to avoid a bulk legacy-data migration; the alias index exposes the corrected canonical name `Guangdong / 广东 / CN-GD`.

## Maintenance rule

Ordinary trip-generation Agents must not select from, directly read, or refresh this library. The alias-integrity check is an independent maintenance safeguard and is not part of ordinary `npm run validate`; it does not make Boundary data an input to the ten-template map Builder. When a maintainer intentionally refreshes the library, they must review the current upstream terms, record the exact source revisions and retrieval date, run `npm run boundaries:index`, and then run `npm run boundaries:validate`. The current `scripts/sync-boundaries.mjs` country source points to a mutable branch, so it must not be presented as a reproducible snapshot until a maintainer has verified and pinned the intended revision.
